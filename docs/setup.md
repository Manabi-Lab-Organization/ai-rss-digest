# 立ち上げ方と運用

AI RSS Digest を自分のサーバで動かすための手順です。上から順に進めてください。

## 1. 用意するもの

- **サーバ**：Docker と Docker Compose が動く Linux のサーバ。2CPU・メモリ4GB 程度が目安です。
- **ドメイン名**（https で公開する場合）：例 `digest.example.com`。サーバの IP アドレスに向けておきます。
- **API キー**：次の「2. API キー」を読んで用意します。
- **このリポジトリ**：GitHub のこのページの「Code」ボタンからアドレスを写し、サーバで `git clone` して取得します。以下のコマンドは、取得したフォルダの中で実行します。

## 2. API キー

API の料金は、各社がそれぞれのサービスに直接払います。

| サービス | 要否 | 使う機能 | `.env` の項目 |
|---|---|---|---|
| Anthropic | 必須 | 紙面の編集・要約、編集長への相談、深掘り | `ANTHROPIC_API_KEY` |
| Gemini | 任意 | 音声版 | `GEMINI_API_KEY` |
| Resend | 任意 | 朝刊のメール配信、パスワード再設定のメール、深掘りや見直し案の完成のお知らせ | `RESEND_API_KEY`・`FROM_EMAIL` |
| Google（OAuth クライアント ID） | 任意 | Google アカウントでのログイン | `GOOGLE_CLIENT_ID` |

- **Gemini は、請求先（お支払い情報）を紐づけた有料枠のキーを使ってください。** 無料枠では、送った内容が Google のサービス改善に使われ、人が読むこともあります。
- **メールは Resend だけに対応しています。** 自社のメールサーバ（SMTP）や、ほかのメール配信サービスからは送れません。Resend にも料金（無料の範囲と上限）があります。
- **Resend** は、送り主にするドメインを Resend で確認済みにし、そのドメインのアドレスを `FROM_EMAIL` に書きます。ドメインの確認とは、Resend の画面に出る DNS の記録（SPF・DKIM など）を、自社のドメインの DNS に足す作業です。DNS を管理している人に頼んでください。
- **Google ログイン** を使う場合は、Google Cloud のコンソールで「ウェブ アプリケーション」の OAuth クライアント ID を作り、「承認済みの JavaScript 生成元」に `APP_URL` と同じアドレスを登録します。どのドメインのアカウントでもログインできます（登録には招待が要ります）。

キーが無い機能は画面に出ません。

## 3. `.env` を書く

```sh
cp .env.example .env
```

`.env` を開き、次の5つを必ず書きます。足りないとアプリは起動を止め、足りない項目を記録（ログ）に出します。

| 項目 | 書く内容 |
|---|---|
| `APP_URL` | このサーバを開くアドレス。例 `https://digest.example.com`（末尾の `/` は付けない） |
| `SESSION_SECRET` | でたらめな長い文字列。`openssl rand -hex 32` で作れます |
| `POSTGRES_PASSWORD` | データベースのパスワード |
| `INITIAL_ADMIN_EMAIL` | 最初の管理者になる人のメールアドレス |
| `ANTHROPIC_API_KEY` | Anthropic の API キー |

**`POSTGRES_PASSWORD` の注意**

- **英数字だけ**にしてください。記号が入るとデータベースの接続先の書き方が崩れ、つながらなくなることがあります。長めにすれば英数字だけで十分です。
- **最初に立ち上げる前に決め、あとから変えないでください。** データベースのパスワードは最初の立ち上げのときに決まります。あとで `.env` だけ変えると、アプリがデータベースにつながらなくなります。

任意の項目は「11. 任意の設定」を見てください。`.env` は他人が読めないようにしておきます（例 `chmod 600 .env`）。

## 4. 立ち上げる

https で公開する方法を2つ用意しています。どちらか一方を選びます。

### A. 同梱の Caddy で https にする（新しくサーバを用意した場合）

Caddy が証明書を自動で取得・更新します。

1. ドメイン名をこのサーバの IP アドレスに向けておきます。
2. サーバの 80 番と 443 番のポートを外から届くように開けます。
3. `.env` に `DOMAIN` を書きます（`APP_URL` のホスト名と同じ。例 `digest.example.com`）。
4. 立ち上げます。

```sh
docker compose --profile https up -d --build
```

### B. すでにある nginx などの後ろに置く

アプリはこのサーバの中だけ（`127.0.0.1` の 3000 番）で待ち受けます。

```sh
docker compose up -d --build
```

nginx の設定の例です（証明書の設定は省いています）。

```nginx
server {
    listen 443 ssl;
    server_name digest.example.com;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
}
```

- `client_max_body_size`：編集長への相談で資料を添付できるようにするためです。
- `proxy_read_timeout`：編集長への相談はウェブを調べるため、返事に時間がかかることがあります。
- ポートを変えるときは `.env` の `APP_PORT` を書きます。

### TRUST_PROXY（前に置いた中継サーバの段数）

アプリは、ログインの試行回数の制限などに、利用者の IP アドレスを使います。中継サーバ（Caddy や nginx）の後ろでは、中継サーバが伝える IP アドレスを何段まで信じるかを `TRUST_PROXY` で決めます。

- A・B のように中継サーバが1段なら、書かなくてかまいません（既定は 1）。
- nginx の前にさらにロードバランサーなどがあり、**中継が2段なら `TRUST_PROXY=2`** にします。
- 中継サーバを置かずに直接開く場合は `TRUST_PROXY=false` にします。

### http で開く場合（外から届かない閉じたネットワークで試すとき）

https を使わずに試すときは、`.env` に次を書いて `docker compose up -d --build` で立ち上げます。

```sh
APP_URL=http://（サーバのIPアドレス）:3000
APP_BIND=0.0.0.0
ALLOW_HTTP=true
TRUST_PROXY=false
```

http ではパスワードなどが暗号化されずに流れます。外から届く場所では使わないでください。

## 5. 立ち上がったか確かめる

```sh
docker compose ps
docker compose logs app
curl -s http://127.0.0.1:3000/api/health
```

- `docker compose ps` で `db` と `app`（A の場合は `caddy` も）が動いていること。
- 記録（ログ）に `[Startup] 必須の設定はそろっています` と `Server running on` が出ていること。まだ利用者がいなければ、`[Setup] 初期設定コード:` の行も出ます（「6.」で使います）。`[Features]` の行で、使える機能（`googleLogin`・`email`・`podcast`）が分かります。
- `curl` の結果に `"status":"ok"` が出ていること。

データベースの表は、アプリが起動するときに自動で作られます。

## 6. 最初の管理者と招待

1. サーバの記録（ログ）から「初期設定コード」を探します。利用者がまだ1人もいないとき、アプリは起動のたびに一回限りのコードを作り、記録にだけ出します。

   ```sh
   docker compose logs app | grep 初期設定コード
   ```

2. ブラウザで `APP_URL` を開き、`INITIAL_ADMIN_EMAIL` に書いたアドレスと、1 の初期設定コードを入れて登録します（Google で登録する場合も、先にコードを入れます）。このアドレスの人だけが最初の管理者になれます。コードは一度使うと無効になります。アプリを立ち上げ直すと新しいコードに変わるので、そのときは記録を見直してください。
3. 2人目からは、管理者の招待が要ります。右上のメニューから管理画面を開き、「招待」で招待を作ります。
   - **1人用**：1回だけ使える招待です。
   - **まとめて配る用**：何人でも使える招待です。
   - どちらも、使える日数を決められます（空欄なら期限なし）。
4. できた招待のリンク（`APP_URL/register?code=…`）を、使ってもらう人に渡します。

**パスワードを忘れた人がいたら**

- メール（Resend）を設定していれば、本人がログイン画面から再設定のメールを受け取れます。
- 設定していなければ、管理者が管理画面の「利用者」でその人のパスワードを再設定し、表示された一時パスワードを本人に伝えます。

## 7. 使い始め方

1. 「編集長に相談」で、追いかけたい業界・企業・テーマを伝えます。編集長（AI）が情報源を探して提案します。
2. 提案された情報源のうち、よいものを承認します。承認したものは「情報源」に並びます。RSS のアドレスや Googleニュースの検索キーワードを「情報源」で自分で登録することもできます。
3. 記事は毎時集まります。「朝刊」で「創刊号を作る」を押すと、たまった記事から最初の号を作ります（数分かかります）。
4. 次の号からは、「設定」で決めた時刻（既定は朝6時）に自動で作られます。配信の頻度（毎日・週3回・週1回）と、メールでも受け取るかどうかも「設定」で決めます。
5. 気になった記事は「深掘り」でレポートにでき、紙面は「音声版」で聞けます（Gemini のキーがある場合）。

**一次情報の扱い**

- 記事の採点では、媒体の名前や知名度で点数を変えません。同じ出来事を多くの情報源がすでに報じていて新しい事実が無い記事は低く、報じる情報源が少なくても重要な事実を含む記事は高く見ます。
- 政府・自治体の公式サイト（`go.jp`・`lg.jp` など）の記事は、一次情報（発表した当事者自身の情報）として扱います。
- 会社や団体が自分で出しているお知らせの RSS などは、「情報源」でその情報源の「一次情報にする」を押すと、一次情報として扱います。既定は「分類しない」です。Googleニュースの検索フィードには設定できません。

## 8. Googleニュースの検索フィードの利用条件

情報源には、Googleニュースの検索結果の RSS（`https://news.google.com/rss/search?q=…`）を登録できます。編集長も、よい RSS が見つからないテーマではこれを提案することがあります。

この RSS には、次の利用条件が英語で書かれています（2026年10月時点）。

> This XML feed is made available solely for the purpose of rendering Google News results within a personal feed reader for personal, non-commercial use. Any other use of the feed is expressly prohibited. By accessing this feed or using these results in any manner whatsoever, you agree to be bound by the foregoing restrictions.

訳：このフィードは、個人が非商用で使うフィードリーダーで Googleニュースの検索結果を表示するためだけに提供されています。それ以外の使い方は明確に禁じられています。このフィードにアクセスしたり、結果をどのような形であれ使ったりすると、この制限に従うことに同意したものとみなされます。

- 会社の業務で使うことや、AI で要約することは、この条件に当てはまらない可能性があります。**使うかどうかは、各社で判断してください。**
- Googleニュースの検索フィードを登録しなければ、アプリが Googleニュースを読みに行くことは一切ありません。編集長の提案も、承認しなければ登録されません。
- 元記事のアドレスを割り出す非公式の仕組みは使っていません。記事の発行元の名前は、RSS の `<source>` から読んでいます。
- Googleニュースの記事のページは取りに行きません。Googleニュースから来た記事は、RSS に書かれている見出しと要約だけで紙面を作ります。

## 9. 記事の取り方

アプリは、登録した情報源の RSS を毎時読み、紙面に載せる記事については、要約を書く材料として記事のページも読みに行きます（最大 6,000 字ほど）。そのときの決まりは次のとおりです。

- **このアプリとして名乗ります。** 相手のサイトには `Mozilla/5.0 (compatible; AI-RSS-Digest/<版>; +https://github.com/Manabi-Lab-Organization/ai-rss-digest)` と伝えます。ブラウザのふりはしません。
- **robots.txt に従います。** 記事のページを読む前に、そのサイトの robots.txt を読み、禁止されていれば読みに行きません。その記事は RSS の要約だけで書きます。robots.txt はサイトごとに 6 時間ためておき、その間は読み直しません。robots.txt が無いサイトは、読みに行きます。robots.txt がサイトの障害で返らない・接続できないときは、robots.txt の決まり（RFC 9309）に従って、1 時間は読みに行きません。サイトの側で `User-agent: AI-RSS-Digest` あての指定があれば、そちらに従います。
- **Googleニュースの記事のページは読みに行きません**（「8.」を参照）。
- 記事を読めなかった理由（「サイトの設定で取得が許可されていない」など）は、記録（ログ）に出ます。

## 10. ニュースの転載・再配布について

- 紙面と音声版は、登録した利用者が自分で読む・聞くためのものです。
- 紙面に載る記事の見出し・要約のもとになった元の記事の著作権は、それぞれの発行元にあります。紙面には元の記事へのリンクを付けています。
- 紙面や音声版を組織の外へ転載・公開・再配布してよいかは、各社が元の記事の発行元の利用規約と著作権を確かめて判断してください。
- Googleニュースの検索フィードの扱いは「8.」のとおりです。

## 11. 任意の設定

`.env.example` にすべての項目と短い説明があります。よく使うものだけ挙げます。

| 項目 | 内容 |
|---|---|
| `GEMINI_API_KEY` | 音声版を使う |
| `RESEND_API_KEY`・`FROM_EMAIL` | メールを送る |
| `GOOGLE_CLIENT_ID` | Google ログインを使う |
| `APP_NAME`・`ORGANIZATION_NAME`・`SUPPORT_EMAIL` | 画面に出すアプリの名前・運営者の名前・問い合わせ先 |
| `TERMS_URL`・`PRIVACY_URL` | 利用規約・プライバシーポリシーのページ（画面にリンクを出す） |
| `OPS_EMAIL` | データベースの容量の警告などを受け取るアドレス |
| `PODCAST_RETENTION_DAYS` | 音声版の音声を残す日数（既定は180日。過ぎたら音声だけ消え、台本から作り直せます） |
| `WEB_SESSION_IDLE_MINUTES` など | ログインの有効期間 |

`.env` を変えたら、立ち上げたときと同じコマンド（`docker compose up -d` や `docker compose --profile https up -d`）をもう一度実行すると反映されます。

## 12. 外部に送るデータ

アプリは、使う機能に応じて次のサービスにデータを送ります。サーバの外向きの通信を、許可した宛先だけに絞っている場合は、「宛先」の列のホストへの https（443 番）を許可してください。

| 送り先 | 宛先 | 送るもの | いつ |
|---|---|---|---|
| Anthropic | `api.anthropic.com` | 集めた記事の見出し・本文、編集方針、編集長への相談の内容と添付した資料、記事への評価・意見、深掘りする記事 | 紙面づくり・相談・深掘り・見直し案づくりのとき。情報源探しと深掘りでは Anthropic のウェブ検索も使います（検索は Anthropic の側で行われます） |
| Gemini（キーがある場合） | `generativelanguage.googleapis.com` | 音声版の台本、読み方を確かめる人名 | 音声版を作るとき |
| Resend（キーがある場合） | `api.resend.com` | 宛先のメールアドレスと、メールの本文（紙面の見出しとリードなど） | メールを送るとき |
| Google（Google ログインを使う場合） | `www.googleapis.com` | ログインの確認に使う公開鍵の取得 | Google でログインするとき |
| 登録した情報源のサイト | 各サイト（http・https） | RSS と robots.txt と記事のページの読み込み（相手にはこのサーバの IP アドレスが届きます） | 毎時の記事集めと紙面づくりのとき |
| Googleニュース（検索フィードを登録した場合） | `news.google.com` | 検索フィードの読み込み | 毎時の記事集めのとき |
| Cloudflare R2（`AUDIT_R2_*` を設定した場合） | `（アカウントID）.r2.cloudflarestorage.com` | 操作の記録 | 1日1回 |

- 情報源のサイトは利用者が自由に登録できるので、宛先をあらかじめ決めきれません。外向きの通信を絞る場合は、情報源の読み込みが止まることを承知のうえで、許可するサイトを決めてください。
- 一方で、**このサーバから自社の重要なシステムへは、外向きの通信が届かないようにしてください**（「13. 安全のために」）。
- 外部のサービスとの通信は https で行います。利用者のブラウザとこのサーバの間の通信が暗号化されるのは、https で公開した場合だけです（「4.」の A・B）。http で開くと暗号化されません。

各サービスでのデータの扱いは、それぞれの利用規約と設定を確かめてください。

## 13. 安全のために

- **https で公開してください。**
- **`INITIAL_ADMIN_EMAIL` を設定してから立ち上げてください**（Docker で動かす場合は、設定しないと起動しません）。最初の管理者の登録には、このアドレスと、サーバの記録にだけ出る初期設定コードの両方が要ります。立ち上げたら、なるべく早く最初の管理者を登録してください。
- **このサーバから自社の重要なシステムへ、外向きの通信が届かないようにしてください。** アプリは利用者が登録したアドレスを読みに行きます。内部のアドレスへの接続は止める仕組みがありますが、ファイアウォールなどネットワークの側でも区切ってください。外へ出る通信の宛先は「12. 外部に送るデータ」にまとめています。
- **`.env` とデータベースのバックアップは、他人が読めない場所に置いてください。** API キーや利用者の情報が入っています。

## 14. 新しい版にする

```sh
git pull
docker compose up -d --build
```

A（Caddy）の場合は `docker compose --profile https up -d --build` です。データベースに足りない表や列は、起動時に自動で足されます。念のため、先にバックアップを取ってください。

## 15. バックアップと戻し方

データ（利用者・情報源・記事・紙面・音声版など）はすべてデータベースに入っています。`.env` も一緒に保管してください。

**バックアップを取る**

```sh
docker compose exec -T db pg_dump -U digest -Fc digest > digest-backup.dump
```

**戻す**

```sh
docker compose stop app
docker compose exec -T db pg_restore -U digest -d digest --clean --if-exists < digest-backup.dump
docker compose start app
```

別のサーバに戻すときは、同じ `.env`（特に `POSTGRES_PASSWORD` と `SESSION_SECRET`）を置き、`docker compose up -d db` でデータベースだけ立ち上げてから戻し、そのあとアプリを立ち上げます。

## 16. 費用の目安（2026年10月時点）

| 項目 | 目安 |
|---|---|
| 朝刊 | 1号あたり数十円 |
| 創刊号（最初の1号） | たまった記事をまとめて読むので、2号目以降より高め |
| 深掘り・音声版 | 1回あたり数十〜数百円（作る前に確認が出ます） |
| サーバ | 2CPU・メモリ4GB 程度で月数千円 |

API の料金は、情報源の数・記事の量・使うモデルで変わります。各サービスの管理画面で使用量の上限を決めておくと安心です。

## 17. 時刻は日本時間

配信の時刻や自動の処理は、サーバの時刻の設定にかかわらず日本時間で動きます。

| 処理 | 時刻（日本時間） |
|---|---|
| 記事集め | 毎時7分ごろ |
| 朝刊づくり | 各自が決めた時刻（既定は6時） |
| 編集方針の見直し案 | 日曜17時 |
| 情報源の提案 | 月1回は毎月1日、週1回は日曜。どちらも18時以降 |
| 古い音声版の削除・容量の確認 | 毎日4時 |

## 18. 使うのをやめるとき

次の順に片付けます。データベースを消すと元に戻せません。

1. **必要ならバックアップを取ります**（「15. バックアップと戻し方」）。
2. **アプリとデータを消します。** 次のコマンドで、アプリを止め、データベースと証明書の保存場所（Docker のボリューム）も消します。`-v` を付けると、利用者・情報源・記事・紙面・音声版がすべて消えます。

   ```sh
   docker compose --profile https down -v
   ```

   B（nginx などの後ろ）で立ち上げた場合は `docker compose down -v` です。
3. **フォルダを消します。** 取得したフォルダと `.env`、残しておく必要のないバックアップを消します。
4. **API キーを無効にします。** Anthropic・Gemini・Resend の管理画面で、このアプリに使ったキーを無効にします。Google ログインを使っていた場合は、OAuth クライアント ID も消します。
5. 外向きの通信の許可や DNS の記録（Resend のドメインの確認、`DOMAIN` の向き先）を設定していれば、それも外します。

## 19. 困ったとき

| 症状 | 確かめること |
|---|---|
| アプリがすぐ止まる | `docker compose logs app` に `必須の設定が足りません` が出ていないか。出ていれば、書かれた項目を `.env` に足す |
| データベースにつながらない | `POSTGRES_PASSWORD` が英数字だけか。最初の立ち上げのあとに変えていないか |
| A で https にならない | ドメイン名がこのサーバに向いているか。80 番・443 番が開いているか。`DOMAIN` が `APP_URL` のホスト名と同じか（`docker compose logs caddy`） |
| ログインしてもすぐログイン画面に戻る | https で開いているか。http で開くなら `ALLOW_HTTP=true` にしているか。`APP_URL` が実際に開いているアドレスと同じか |
| 音声版・メール・Google ログインが出ない | 対応するキーを `.env` に書いたか。管理画面の「利用状況」で確かめる |
| 「利用状況」では使えることになっているのに、朝刊・相談・深掘り・音声版・メールが失敗する | キーが正しいかどうかは、起動のときも「利用状況」でも確かめていません（書いてあるかどうかだけを見ています）。`docker compose logs app` でそのサービスのエラーを探します。キーの写し間違い（前後の空白・欠け）、残高やお支払い情報の未設定、利用の上限に達していないかを、各サービスの管理画面で確かめます。キーを直したら `docker compose up -d`（A は `docker compose --profile https up -d`） |
| 記事が集まらない・外部のサービスにつながらない | サーバの外向きの通信を絞っていないか。「12. 外部に送るデータ」の宛先を許可しているか |
| 最初の管理者を登録できない | `INITIAL_ADMIN_EMAIL` と同じアドレスで登録しているか（書き間違えていたら `.env` を直して立ち上げ直す）。初期設定コードを `docker compose logs app \| grep 初期設定コード` の最新の行から写したか（立ち上げ直すとコードが変わります） |
| 朝刊が届かない | 情報源が1つ以上あるか。「設定」の時刻と頻度。メールで受け取るなら Resend の設定 |
| 音声版がうまく作れない | `docker compose logs app` の記録。Gemini のキーが有料枠か |

解決しないときは、GitHub の Issues で知らせてください（日本語のみ。できる範囲で回答します）。
