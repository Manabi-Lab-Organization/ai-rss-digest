# AI RSS Digest

一人ひとりが追いかけたいテーマに合わせて、AI が毎朝の紙面（朝刊）を作るウェブアプリです。
自分のサーバに Docker で立ち上げ、自分の API キーで動かします。ソフトの料金はかかりません。

- **向いている使い方**：組織の何人かで、それぞれが追いかけたいニュースを毎朝短く読みたい場合。サーバの立ち上げと管理は、自社で行います。
- **データの行き先**：利用者・情報源・紙面などのデータは、自社のサーバのデータベースに入ります。記事の要約や紙面づくりのために、記事の本文や編集方針などを、使う API の会社（Anthropic、音声版を使うなら Google の Gemini、メールを使うなら Resend）に送ります。記事は登録した情報源のサイトから読み込みます。詳しくは [docs/setup.md](docs/setup.md) の「外部に送るデータ」を読んでください。
- **ニュースの扱い**：紙面と音声版は、登録した利用者が自分で読む・聞くためのものです。元の記事の著作権は各発行元にあり、組織の外への転載・再配布は各社の判断です（[docs/setup.md](docs/setup.md) の「ニュースの転載・再配布について」）。

## 何ができるか

- **編集長に相談**：追いかけたい業界・企業・テーマを AI の「編集長」に伝えると、合いそうな情報源（ニュースサイトの RSS や Googleニュースの検索キーワード）を探して提案します。資料（画像・PDF・テキスト・Word）を添えて相談することもできます。
- **情報源の承認**：提案された情報源のうち、承認したものだけを登録します。RSS のアドレスや検索キーワードを自分で登録することもできます。
- **毎朝の紙面**：登録した情報源から記事を毎時集め、決めた時刻（日本時間。既定は朝6時）に、その人向けの紙面を作ります。配信は毎日・週3回・週1回から選べます。紙面は画面で読み、メールでも受け取れます（メールの設定がある場合）。
- **紙面への評価と見直し**：記事に評価を付けたり、編集長に意見を送ったりできます。たまった評価と意見をもとに、AI が週に一度（日曜の夕方）編集方針の見直し案を作り、承認すると次の号から反映されます。新しい情報源の提案も定期的に届きます（月1回・週1回・止める、から選べます）。
- **深掘り**：気になった記事について、AI がウェブも調べてレポートにまとめます。図解付きの版も作れます。
- **音声版**：紙面を2人の掛け合いの音声（ポッドキャスト）にします。
- **管理画面**：利用者の管理、招待、利用者へのお知らせ、利用状況（どの機能が使えるか）の確認ができます。

深掘り・音声版のように費用がかかる操作は、作る前に確認が出ます。

## 要るキーと使える機能

| キー | 要否 | 使う機能 |
|---|---|---|
| Anthropic | 必須 | 紙面の編集・要約、編集長への相談、深掘り |
| Gemini | 任意 | 音声版（請求先を紐づけた有料枠のキーを使う） |
| Resend | 任意 | 朝刊のメール配信、パスワード再設定のメール、深掘りや見直し案の完成のお知らせ |
| Google の OAuth クライアント ID | 任意 | Google アカウントでのログイン |

キーが無い機能は画面に出ません。管理画面の「利用状況」で、どの機能が使えるかを確かめられます。

## 始め方

用意するのは Docker が動くサーバ（2CPU・メモリ4GB 程度）と、Anthropic の API キーです。

このリポジトリを取得し、そのフォルダで次を実行します。

```sh
git clone https://github.com/Manabi-Lab-Organization/ai-rss-digest.git
cd ai-rss-digest
cp .env.example .env
# .env に APP_URL・SESSION_SECRET・POSTGRES_PASSWORD・INITIAL_ADMIN_EMAIL・ANTHROPIC_API_KEY と DOMAIN を書き込む
docker compose --profile https up -d --build
```

https の用意のしかた、最初の管理者の登録（サーバの記録に出る初期設定コードを使います）、利用者の招待などは [docs/setup.md](docs/setup.md) を読んでください。
